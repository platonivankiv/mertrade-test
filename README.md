# Тестовое задание МЭР Трейд — инженер по интеграциям

## Состав

| Папка | Задание |
|---|---|
| `04/` | Разбор обращений сотрудников по логам (обязательное) |
| `03/` | B2B-сайт: почему у клиента «не та» цена |
| `06/` | Своё улучшение |

Почему выбрал 03: я frontend-разработчик, и задачи вида «пользователь видит не те данные» — моя ежедневная работа: разобраться, где ошибка — в коде, в данных с бэкенда или в кеше. В 03 ровно такая задача: пять обращений, у каждого своя причина (код, данные, кеш или ожидания, расходящиеся с правилами), и её нужно доказать, а не угадать. Кешированием и согласованностью данных я много занимался на фронтенде (TanStack Query, Apollo, опрос сервера в MBOptions), поэтому случай с устаревшим кешем мне особенно близок.

## Как запустить

Требуется PHP 8.1+.

```bash
cd 03
cp var/cache.json var/cache.orig.json   # run.php перезаписывает кеш
php run.php K-001 B-101
php tests/scenarios.php                 # сценарии по 5 обращениям, без зависимостей
```

## Принятые решения

- 03: при отсутствии цены нужного типа `PriceResolver::basePrice()` бросает исключение вместо подстановки розничной цены — продавать по чужой цене хуже, чем явно показать, что цены нет.
- 03: кеш в `PriceResolver.php` не меняю (правка «не больше, чем нужно»); случай №4 закрывается сбросом кеша, профилактика описана в `03/03-answers.md`.
- 03: тесты — `03/tests/scenarios.php` без PHPUnit, кеш пишется во временный файл, `var/cache.json` не трогается.
- 03: акция действует до конца дня `valid_to` по времени Минска (`run.php:32`).
