# Прототип: мониторинг обменов с 1С

PHP 8.1+, без зависимостей. Скрипт только читает данные и печатает алерты, ничего не пишет.

## Файлы

- `monitor.php` — скрипт с правилами.
- `shops.json` — пороги, дедлайн отчёта магазинов (22:00), праздники, магазины и их рабочие дни (ISO: 1 — пн … 7 — вс). Магазин №4 по средам не работает.
- `data/incident/` — выдуманные данные в духе inc3 и inc4: очередь стоит на заказе клиента K-117, смена 1188 магазина №2 пропущена (`skipped=143 errors=0`).
- `data/ok/` — те же данные без сбоев. На них не должно быть ни одного алерта.

`queue.json` повторяет поля `exchange_queue` из `queue_snapshot.txt`, к ним добавлено поле `last_error`. `retail_exchange.csv` — итоговые строки `done: created=… skipped=… errors=…` из `exchange_retail.log`, по одной строке на смену.

## Правила

| Правило | Уровень |
|---|---|
| Самое старое задание в `pending` ждёт дольше 15 мин | срочно |
| У незавершённого задания больше 5 попыток | срочно |
| У магазина нет загруженного отчёта за рабочий день (до 22:00 проверяется вчерашний день, после 22:00 — сегодняшний) | сводка |
| `skipped > 0` при `errors = 0` за последние сутки, без учёта расписания | сводка |
| Не удалось прочитать данные | срочно |

## Запуск

Из корня репозитория:

```bash
php 06/prototype/monitor.php --now="2026-10-22 08:20"
```

```bash
php 06/prototype/monitor.php --data=06/prototype/data/ok --now="2026-10-22 08:20"
```

`--data` — папка с данными (по умолчанию `data/incident`). `--now` — «текущее время», нужно, чтобы вывод на выдуманных данных был воспроизводимым. Код возврата: 0 — замечаний нет, 1 — есть алерты.

## Вывод

На `data/incident` (утро 22.10, как в inc3):

```
Мониторинг обменов с 1С, сейчас 2026-10-22 08:20

СРОЧНО (сразу в чат):
  - Очередь стоит: заданий в pending — 3, самое старое #88414 ORD-B2B-7781 ждёт 22 мин (порог 15)
  - Задание #88414 ORD-B2B-7781: попыток — 23 (порог 5), последняя ошибка: HTTP 422: Контрагент не найден (client K-117)

В СВОДКУ (утром):
  - Магазин №2: нет отчёта о розничных продажах за 21.10.2026 (проверка после 22:00)
  - Магазин №2, смена 1188 (2026-10-21 21:03:15): пропущено 143 из 143 чеков при errors=0
```

Магазины №1 и №3 отчитались, магазин №4 21.10 (среда) не работал, поэтому алертов по ним нет.

На `data/ok`:

```
Мониторинг обменов с 1С, сейчас 2026-10-22 08:20
Всё в порядке: очередь движется, отчёты магазинов на месте.
```

## Чего нет в прототипе (для рабочей версии)

- Чтение из БД (`SELECT` под пользователем только с правом чтения) и разбор `exchange_retail.log` вместо JSON/CSV.
- Отправка в Telegram: `curl` на `https://api.telegram.org/bot<token>/sendMessage`. Срочное отправляется сразу, остальное собирается в утреннюю сводку.
- Защита от повторов: одна и та же проблема напоминает о себе не чаще раза в час. Для этого нужно хранить, что уже отправлено.
- Магазин №2 сейчас даёт два алерта: нет отчёта и пропущенные чеки. Оба верные, но в сводке их можно объединить в одну строку.

Пример cron:

```
*/5 * * * * php /path/to/monitor.php
```
